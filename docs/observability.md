# Observability with OpenTelemetry

This project uses OpenTelemetry for local distributed tracing across the order workflow:

```text
order-service -> workflow-service -> inventory-service
```

The preferred local setup is the OpenTelemetry Java Agent plus an OpenTelemetry Collector and Jaeger in Docker.

## Start the observability stack

```powershell
docker compose up -d otel-collector jaeger
```

Jaeger UI is available at:

```text
http://localhost:16686
```

The Collector accepts OTLP at:

```text
http://localhost:4318
localhost:4317
```

## Download the Java Agent

```powershell
.\scripts\download-otel-java-agent.ps1
```

This downloads `tools/opentelemetry-javaagent.jar`.

## Run the instrumented services

Open three terminals:

```powershell
.\scripts\start-otel-service.ps1 -Service workflow-service
.\scripts\start-otel-service.ps1 -Service inventory-service
.\scripts\start-otel-service.ps1 -Service order-service
```

Create an order through `order-service`:

```powershell
curl.exe -X POST http://localhost:8081/api/orders `
  -H "Content-Type: application/json" `
  -d '{ "orderId": "order-otel-1001", "customerId": "customer-42", "orderAmount": 120.50, "currency": "USD", "sku": "SKU-DEFAULT", "quantity": 1, "correlationId": "correlation-otel-1001" }'
```

Then open Jaeger and search for `order-service`. A successful trace should include server spans, REST client spans, JDBC spans, and custom business spans such as:

- `order.create`
- `workflow.start`
- `bpmn.validate_order`
- `bpmn.reserve_inventory`
- `inventory.reserve`
- `bpmn.charge_payment`
- `bpmn.complete_order`

## Simulate an insufficient-stock trace

```powershell
curl.exe -X POST http://localhost:8081/api/orders `
  -H "Content-Type: application/json" `
  -d '{ "orderId": "order-otel-reject-1001", "customerId": "customer-42", "orderAmount": 120.50, "currency": "USD", "sku": "SKU-DEFAULT", "quantity": 1000, "correlationId": "correlation-otel-reject-1001" }'
```

The trace should show the inventory conflict, `bpmn.reserve_inventory` with error status, and the `bpmn.reject_order` path.

## What is instrumented

The Java Agent automatically instruments Spring MVC, RestTemplate, JDBC, Hikari, JVM metrics, and log correlation. The code also adds custom spans around key business operations and Camunda delegates so traces are readable at the order-workflow level.

Logs include `trace_id` and `span_id` in `order-service`, `workflow-service`, and `inventory-service` when the application is run with the Java Agent.

The local startup script excludes common non-business server URLs such as Actuator, Prometheus, favicon, Camunda webapp assets, and static resources. The Collector also drops noisy `workflow-service` spans named `GET /**` and `ResponseFacade.sendError`, which are typically generated by unmatched/static requests rather than order-processing workflow calls.
